# S30 — Lists the agent keeps

- **Status:** done
- **Started:** 2026-09-16
- **Finished:** 2026-09-16
- **Goal:** The companion keeps lists for the player — the first and best one being a packing list for a build run — shown in the console and on a read-only panel in the game, so nobody gets to the outpost and finds they forgot the belts.
- **Acceptance:** "I'm building a smelting outpost: 20 ovens, a couple hundred belt, arms to feed them, chests for storage" becomes a list with real numbers and the things the save's data says it also needs (fuel or poles); the list survives a reload and a server restart, per map; the in-game panel shows it with a key and can't be clicked; "am I ready?" answers have / need / missing with what fits in the player's free slots and what's craftable now, and the list ticks itself off as the items arrive in the inventory; the list tool's cost to the cached prompt is measured before and after; the model never edits a list the player didn't ask about; mod per-tick cost unchanged; existing suites still pass.

## Review

The companion keeps lists for the player, and the packing list turns "20 ovens, a couple hundred belt, arms to feed them and chests" into something that can't be forgotten at the base.

- Built: the list primitive (several named lists, one active, one `update_list` tool, saved with the map's conversation), a read-only panel in the game on Alt+L, a `stock` look for what the player can reach, the packing rule (counts, ticking off, "am I ready?" with the slot check), the save's own data adding fuel and poles with reasons, and the bots filling the shortfall from the companion's own request section.
- Measured: the list tool cost the cached prompt nothing (system prompt 3,876 tokens, first token median 1.29 s against 1.55 s before it); stock reads 22 containers in 0.58 ms; the panel and request actions are 0.09–0.98 ms on demand; mod benchmark 0.031 ms/tick with per-tick script time unchanged at 0.05 ms.
- Tests: 188 unit tests; in-game panel 7/7, requests 9/9, player 30/30; through the server packing 5/5; regressions all green (grounding 10/10 at 1.32 s median, pointing 9/9, voice replay 8/8, measure 3/3).
- Found and fixed along the way: the rule used to run a turn late (so the first answer missed both the additions and the ticking); the model wrote a count change as a second line (the tool grew `set`); items sharing one word were treated as the same item ("50 iron gear wheel" overwrote "5 iron chest"); a stale list outlived its conversation (reset clears lists now); the first fuel pick was the *least* energetic and the first pole pick covered the least ground.

**Docs (2026-09-16, at the player's request):** README has a "Packing lists, so you don't arrive without the belts" section, a "What you're pointing at" section, an in-game keys table (Alt+V, Alt+L, Alt+X, the selection shortcut), new first questions to try, two troubleshooting rows and captures of the list in the console and on the in-game panel. The website has a packing-list feature block with the in-game capture, a "What is this?" block, four new "also" cards, a nav link, and its stats updated (0.05 ms of script time, ~1.5 s to first words). Built, not deployed — that's the player's call. Three fixes fell out of writing the docs: a build description now defaults to a *packing* list even when the model forgets to say so, the ask guard lets a build description edit the list without the word "list" in it, and the server sends the lists when a page connects (a reloaded console showed no panel until the next change).

**For the player to check:** say "I'm building X, I need…" and watch the panel in the game (Alt+L) while you gather; then "am I ready?" before you walk out, and "can the bots bring the rest?" if you're in range of your network. Two judgement calls worth a look: on this save the fuel pick is carbon (there are thousands in reach, which beats coal), and "ovens" resolved to stone furnaces in most runs but electric furnaces in one.
